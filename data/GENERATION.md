# data/GENERATION.md

## 合成数据生成规则

所有实验数据均为合成，场景虚构。生成方式：

### 参数设定

- **种子**：20260915（mulberry32 PRNG）
- **方法**：binomial 抽样 —— 给定 (baseline, treatment, n)，用二项分布抽出 xControl 和 xTreatment
- **统计量**：用 zTest 和 newcombeInterval 计算 p 值、置信区间，写入 stats 字段
- **复现**：种子不变，输出完全一致。`npm run gen:experiments`

### 场景设计原则

1. **生活化**：新人优惠券、结算按钮、推送时机、瀑布流、搜索框、商品详情、订单确认、新人引导、评价晒图、会员续费 —— 都是消费类 App 常见场景，不涉及任何实习公司内部业务
2. **数字合理性**：转化率 4.6%-71%，样本量 2800-40000，实验周期 5-14 天
3. **决策分布**（符合任务要求）：
   - 可全量：4 个
   - 不推：4 个（其中 3 个不显著，1 个「显著但业务上不值得」= exp-003）
   - 继续跑：1 个
   - 回滚：1 个

### 复盘文字里的数字全部由代码算出

第一版把复盘那句话手写了，结果和抽样出来的数字对不上：exp-001 抽出 +3.08 个点、文案写「提升 2.5 个点」；exp-003 抽出 p = 0.15（不显著），文案却写「显著（p = 0.02）」。

数据是合成的，但**文案和数字对不上是真的错误**。现在复盘里的定量部分全部由 `zTest` / `newcombeInterval` 的输出拼出来，人只写不含数字的业务判断。脚本里还加了两道断言：

1. **决策与统计结论必须一致** —— 标「全量」就必须显著且为正，标「回滚」就必须显著且为负，否则直接抛错
2. **「继续跑」vs「不推」用和 `interpret()` 完全相同的规则** —— 按观测到的效应量算，达到 80% power 需要的样本量 ≤ 当前 3 倍才算「继续跑」。exp-005 第一版标了「继续跑」，实际要 36 倍样本，被这道断言拦下并重新调参

### 「继续跑」那一条为什么需要重抽

「继续跑」要求观测到的 z 落在约 1.62~1.96 这个窄窗口里（1.96 以上就显著了，1.62 以下就超出 3 倍阈值了）。单次抽样命中该窗口的概率只有一成多，所以 exp-005 允许按固定顺序重抽，直到落进窗口。种子固定 → 重抽序列固定 → 结果仍然可复现。抽了几次记在数据里的 `resampleAttempts` 字段，不藏着。
